An audit of everything one AI agent wrote — and a map of where the choices actually were.

Generation is cheap now. The scarce thing is the act of choosing, and a choice leaves a trace you can count. So instead of generating more, we went back through 253,673 words an agent had already published and asked, sentence by sentence: did anyone choose this, or did it arrive by itself?

The brief

“What matters when you can generate anything? Can you explain your choices?”

The brief asks for taste, which is usually unmeasurable — so it usually gets answered with adjectives. We tried to answer it with a number instead.

Our claim: slop is not bad writing. Slop is a decision nobody made. A decision leaves evidence. It names a specific thing, a number, a link, a constraint. Inherited text leaves the opposite evidence: its wording already existed somewhere else.

Both are countable. That is the whole idea.

The two measurements

1 · THE FRAME. Mask out every number, ticker, handle, date, version and CVE id — so “price rose 4%” and “price fell 9%” become the same sentence. A sentence whose remaining 5-word sequences already appear in 3+ other documents was not written for this document. It was inherited.

2 · THE CONTENT. Verifiable anchors — urls, handles, tickers, CVE ids, issue numbers, versions, quantities with units, currency, addresses, paths, code. Anchor density per 1,000 words, measured over the non-inherited sentences only, so a document made entirely of recycled text scores zero by construction.

A document that is mostly frame, wrapping little that is checkable, contains almost no decisions. That is the definition this audit uses — stated up front, and re-runnable by anyone.

Why this is worse than lazy writing

The digest series published daily at 12:00 for 87 days — 35,604 words — at 80.6% inherited text. Because the frame wrote the sentences, no one noticed when a sentence stopped making sense. patch Obstacles to Weaponizing PHP2Shell Likely Constrain Immediate Widespread Exploit and verify the fix held. That is not a decision. That is a slot machine with a cron job.

The counter-finding

The slop isn't the model. It's the deadline.

An audit that only finds rot is not an audit, it's a prosecution. So we audited a second surface: 930 commit messages the same agent wrote between 2026-02-17 and 2026-10-26.

Result: — of — distinct commit frames were used exactly once. The agent's commit messages are specific, dated, and almost never recycled. Whatever is wrong here, it is not that the model can't tell the truth about its own work.

The number that explains everything

Documents written because someone needed them: — inherited prose.

Documents published because a scheduler said so: — inherited prose.

Slop is not what a model writes. Slop is what happens when a schedule writes instead of a person. The fix isn't a better model. It's a reason to publish, or nothing gets published.

What a chosen sentence looks like

An audit that stops at the diagnosis is criticism. Here is the same slot, written on purpose, with the reasoning shown. The rewrite is authored for this page — the measurements beside it are real.

  1. A sentence that works in any document works in no document.Test applied first: if the line survives being pasted into an unrelated item, it carries no information about this one and gets deleted.
  2. Name a thing that exists.“agents fail in prod” is a category. Substitute the specific artefact, build or incident — the reader can go and check it.
  3. Attach a date, a version or a path.Anchors are the fingerprint of a decision. One date turns a claim into a record.
  4. Say the uncomfortable part.The useful line here is that an old version was left running. Generic reassurance is the cheapest thing a model can produce; the specific risk is the only thing worth printing.
  5. Re-measure.Inherited frames 80.6% → 0%. Checkable anchors in the original remainder: 21 → 34 per 1,000 words. If the numbers don't move, the rewrite was decoration.

Method, and what we did not do

Re-runnable, and honest about the edges

Corpus rule

Excluded by name: node_modules, .git, dist, venv, site-packages, lib, vendor, third_party, submodules, assets, public — and every LICENSE / NOTICE / COPYING / CHANGELOG. Auditing an agent on its dependencies' prose would be dishonest; an earlier run did exactly that and put eight §LICENSE files at the top of the table. We threw that run away.

Also thrown away: a first version that counted bare digits as anchors. It scored 220 of 252 documents as clean, which is the tell of a metric that measures nothing. The anchor set was rewritten to require verifiable specifics only.

# reproduce every number on this page
git clone <repo> && cd non-slop
python3 engine.py --root <repo>  # 252 docs, 253,673 words
python3 commits.py <repo>        # 930 commit frames
# stdlib only. no keys. deterministic.

Reducto

Makes the unreadable auditable — and locates slop by region

The corpus contains — binary artifacts. No text engine can audit a PDF, a scan, a slide export or a generated image. Reducto's parse turns them into structured text so they can be measured at all — and because it returns layout boxes, slop can be scored per region of a page instead of per file. That is the difference between knowing a document is 80% inherited and seeing exactly which boxes on it are.

# POST https://platform.reducto.ai/parse
-H "Authorization: Bearer $REDUCTO_API_KEY"
{"input": "<url|upload_id>", "chunk_mode": "page"}

Pangram

The authoritative verdict we deliberately left out of the headline

Pangram answers “was this written by a machine?”. Our frame metric is deliberately not that question — it measures inheritance, not authorship, and we would rather ship a smaller true claim than a bigger borrowed one. Pangram's job here is to validate the frame metric against a real detector: if documents our method calls TEMPLATE do not score as machine-written, our method is wrong and we want to know.

# POST https://text.external-api.pangram.com/task
-H "x-api-key: $PANGRAM_API_KEY"
{"text": "<document>", "model": "pangram-4"}
# then GET /task/{id} until stage == STAGE_SUCCESS
